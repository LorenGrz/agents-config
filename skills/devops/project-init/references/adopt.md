# Adopting an existing repo
Read when: the repo was not generated by project-init and already has its own history, CI and flow.

Use `scripts/adopt.sh` instead of `init.sh`. Adopt is docs-only: it never adds hooks, CI, ESLint, pre-push, or branch protection - any of those would break whatever the repo already does. It documents the repo's CURRENT reality (a "Workflow contract" table that may legitimately say "nothing (convention only)" in every row) and only RECOMMENDS stronger enforcement in its output, capped at 3 bullets.

1. Create a worktree from the repo's default branch - never touch the user's own working tree/branch, which may be dirty or mid-task:
   ```
   git -C <repo> fetch origin
   git -C <repo> worktree add ../<repo>-adopt -b docs/workflow-contract origin/<default>
   ```
   (`<default>` is whatever `git symbolic-ref --short refs/remotes/origin/HEAD` reports, `main`/`master` otherwise.)
2. Run `bash scripts/adopt.sh --dir ../<repo>-adopt` (add `--dry-run` to preview, `--json` for machine-readable output). It detects the default/dev branch, branch protection, merge settings, branch naming and commit-message history, CI, hooks, PR/issue templates, and package manager/scripts, then fills in or creates `AGENTS.md` (with the Critical rules block), `.agents/CONTEXT.md`, `docs/decisions/{0000,0001}-*.md`, and `docs/plans/HANDOFF.md` - never overwriting a file that already carries real content. Idempotent: a second run makes no changes.
3. `CLAUDE.md` handling: none is created (`--claude-shim` adds a one-line `@AGENTS.md` pointer) and an existing one is never modified or deleted, except that real content in a `CLAUDE.md` with no `AGENTS.md` moves into the new `AGENTS.md` and `CLAUDE.md` becomes the pointer. On a repo whose `AGENTS.md` lacks the baseline markers, `adopt.sh` appends the Critical rules block once.
4. Review the diff in the worktree, especially the generated "Workflow contract" table - fix anything detection got wrong before committing.
5. Commit there: `git -C ../<repo>-adopt add AGENTS.md .agents docs && git -C ../<repo>-adopt commit -m "docs: add workflow contract and agent docs"`.
6. Push and land the change following the **repo's own** workflow, not this skill's: open a PR if the repo already uses PRs or has branch protection, otherwise `git merge --no-ff` straight into the default branch. Pushing needs the user's OK.
7. Remove the worktree: `git -C <repo> worktree remove ../<repo>-adopt` (and delete the branch if it wasn't merged with `--no-ff` locally first).
